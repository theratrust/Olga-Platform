# Source-of-truth gap audit: current Olga Coaching DEV bot

Scope: static audit of the repository on `feature/method-core`, 11 October 2026. Normative IDs refer to [источник_истины_метода_Ольги.md](../method/источник_истины_метода_Ольги.md). No live model, Telegram, DB, or user conversation was inspected. `IMPLEMENTED` means a rule is explicit in the current prompt/code, **not** that every generated answer obeys it. `UNVERIFIED` is used where output or evaluator performance cannot be inferred from source. Severity is user-facing risk, not a measured incident rate.

## Source boundary and files inspected

The repository has no independently inspectable Olga interview transcript or real Olga coaching dialogue. `метод_Ольги.md` and `принципы.md` label three positions directly confirmed, but the primary record is absent. `карта_коучингового_разговора.md §Назначение и происхождение` and `knowledge/evaluation/метод_Ольги_оценка.md §Приоритет источников` acknowledge this. `shadow_light/source/test_iz_teni_v_svet_original.md` is a source placeholder, not the original content. The eight `примеры_коучинговых_разговоров.md` dialogues are expressly synthetic. These facts constrain confidence throughout; the audit does not upgrade derived text into Olga's own speech.

Reviewed method/discovery: all top-level `knowledge/method/*.md`, eight canonical synthetic dialogues, Shadow/Light source placeholder, framework, style, results, journeys, article stub, version welcome notes, `knowledge/discovery/*`; searched repository for interview, article, newsletter, Telegram/email copy and real sessions. Reviewed implementation: `prompts/coaching.py`, `services/methods/loader.py`, `services/coaching_generator.py`, `services/conversation_state.py`, `services/CONVERSATION_STATE.md`, `database.py`, `handlers/chat.py`, `handlers/voice.py`, `handlers/start.py`, `handlers/quiz.py`, `handlers/callbacks.py`, `bot.py`, benchmark path, `knowledge/implementation/AI_поведение_gap_analysis.md`. Reviewed evaluation: both `knowledge/evaluation/*.md`, methodology/quality prompt and shadow runtime modules, synthetic corpora and benchmark documentation. No generic external coaching material was used.

## Current behavior in brief

`prompts/coaching.py:4–100` contains the core prohibitions and loads five method files via `services/methods/loader.py:9–15,41–64`; it does **not** load the conversation map, behavior document, or synthetic dialogues. The generator sends one system message plus chronological history and optional runtime memory (`services/coaching_generator.py:13–33`), with `max_tokens=350`. `handlers/chat.py:82–125` atomically admits the user turn, reads the latest 20 messages in the current DB conversation, builds a conservative older-event ledger, and passes both to the generator. `database.py:301–319` scopes reads by user and conversation ID. The ledger retains at most four explicit older boundary/correction or rejected-hypothesis events (`services/conversation_state.py:9–38,90–182`); it does not retain answered items generally. `/new` rotates the DB session and clears prior history (`handlers/chat.py:40–62`, `database.py:200–238`). Evaluators observe **after** delivery/draft creation (`handlers/chat.py:219–230`); their scores do not edit the user-facing candidate.

## Answers to the twelve quality questions

1. **Generic language:** The prompt loads project method files rather than outside coaching theory. Some loaded working moves (`паттерны.md`) and unloaded Shadow/Light style text are derived and may sound generic if copied; there is no evidence they are Olga's exact wording. Do not label ordinary coaching phrasing as her voice.
2. **Too many questions:** The prompt explicitly warns against a series. Actual current model rate is unverified. Synthetic dialogues 1 and 6 have successive early questions, so they are weak guides for rhythm.
3. **Reflect then question by default:** Not required by the prompt or canonical examples. Actual model habit is unverified without outputs.
4. **Already-answered questions:** Can recur after the answer leaves 20 raw messages because the ledger excludes general answered items. Inside the window, model attention remains unverified.
5. **Options after «я не знаю»:** Explicitly prohibited, including question-shaped candidate states (`prompts/coaching.py:50–64`); actual compliance unverified.
6. **Unsolicited hypotheses:** Prompt permits only user-grounded hypotheses. No deterministic verification of generated grounding; actual incidence unverified.
7. **Persistence after rejection:** Method/evaluator forbid pressure; ledger carries some old explicit rejections. Actual response after refusal unverified, and conservative extraction can miss cases.
8. **Partner/work framing:** Derived behavior docs and examples reject automatic blame/solution. The generator receives general grounding rules, not those specific examples; actual bias unverified. The quiz fallback creates a separate invented context concern.
9. **Client authorship:** Strong instruction and evaluator coverage; not a behavioral guarantee. Repeated questions or suggested answers would erode it.
10. **Natural/specific vs abstract:** Base prompt favors natural specificity, quality evaluator can assess it; actual output unverified. The fixed “Спасибо за твой вопрос” is concretely generic.
11. **Synthetic dialogues:** They respect major hard boundaries, but are not authoritative Olga conversations. Some exchanges show repetitive questioning or a nearly redundant hypothesis; detailed review below.
12. **Evaluators:** Hard-fail specification aligns with core boundaries and quality specification expressly permits no-question pauses. `progression` can create a soft incentive to move too fast; semantic enforcement of subtle violations is unverified. Shadow observers do not affect the current response.

## Evaluator audit and conceptual corrections

Method evaluator HF01–HF08 covers the hard bans, including question-shaped substitutions after «я не знаю», tentative diagnosis, archetype-as-proof, and post-rejection pressure. Its `client_authorship` and `grounding` scores cannot offset a hard fail by specification. Source references are checked for valid files/headings, but that cannot independently authenticate an interview. Keep the distinction between secondary attestation and primary quotation visible in evaluator reports.

Quality evaluator explicitly says absence of a question is not a fault, that a short uncertainty response may be strong progression, and that quality cannot compensate for method failure. It penalizes generic reflection, repeated structure, generic question, and context miss. A remaining **measurement risk** is whether actual quality judgements reward “another useful question” more than a warranted pause, or miss subtle ready-made answers in question form. Conceptually add contrastive synthetic qualification pairs and a priority check that any proven HF violation remains disqualifying regardless of quality score. Do not add a new dimension or change runtime routing in this task.
