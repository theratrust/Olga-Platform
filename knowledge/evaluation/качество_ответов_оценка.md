# Оценка качества ответа Olga Coaching

## Статус и происхождение

Версия: 1.0. Происхождение всех рубрик, баллов, Q-флагов и синтетических меток:
derived_product_quality_criteria — производные продуктовые критерии качества.
Это не прямые высказывания Ольги и не новые правила её метода. Источники метода
не изменяются и не используются для повышения статуса этих критериев.

Оценщик метода отвечает: «Есть ли нарушение метода?» Его предмет — границы,
верность методу и HF01–HF08. Отдельный оценщик качества отвечает: «Насколько этот
ответ конкретен, естественен и полезен для продолжения разговора?»
Методологически допустимый ответ может иметь слабое продуктовое качество.
Сильное качество не доказывает методологическую допустимость и не компенсирует
нарушение метода. Q-флаг не является HF-нарушением. Здесь нет hard_fail, решения
accept/retry/escalate или влияния на пользовательский ответ.

Это офлайн-спецификация. Нет интеграции в runtime, второго shadow worker,
модельных вызовов или изменений генератора. Метки корпуса созданы вручную из
этой рубрики, а не из ответов GLM. Разногласия по качеству требуют отдельного
продуктового рассмотрения; рубрика не приписывает Ольге непроверенные правила.

## Вход

Обязательные непустые строки: user_message и candidate_response.
conversation_context — необязательный массив предшествующих сообщений в
хронологическом порядке: {role: user|assistant, content: строка}. Пустая строка
контента допустима; пустой массив может означать начало разговора, а не пробел.
Нельзя выдумывать отсутствующие ходы или скрытые эмоции/мотивы пользователя.
recent_assistant_response_patterns — необязательный массив непустых строк с
подсказками о недавних паттернах в этом же разговоре. Подсказки не заменяют
реальные реплики и сами не служат доказательством Q-флага.

Одна отражающая реплика не является автоматически шаблоном. Для устойчивого
повтора сравниваются конкретные предшествующие ответы и текущий кандидат.
Повтор один раз может быть полезен: например, пользователь просит повторить
вопрос. Одинаковые структуры в нескольких последовательных ходах могут быть
слабостью, если не добавляют смысла. Отсутствие вопроса не является недостатком.

## Измерения и баллы

Шкала каждого измерения: 2 — явно сильная сторона; 1 — конкретная некритичная
слабость; 0 — доказанный провал качества; null — именно это измерение нельзя
безопасно оценить из-за существенно отсутствующего контекста.

| Измерение | 2 | 1 | 0 |
|---|---|---|---|
| contextual_specificity | Точно работает с особым смыслом текущего материала | Связь есть, но часть формулировки общая | Реплика почти взаимозаменяема с ответом на любой запрос либо упускает ключевой смысл |
| progression | Добавляет полезное различение или следующий шаг исследования | Есть небольшой шаг, но ответ в основном остаётся на прежнем уровне | Практически только пересказывает, без нового полезного фокуса |
| non_repetition | Нет лишнего пересказа; повторы оправданы контекстом | Один лишний повтор, не превращающий беседу в механическое зеркало | Много ненужного пересказа либо одно строение последовательно заменяет движение разговора |
| naturalness | Живой, связный и естественный отклик | Заметен небольшой канцеляризм или искусственная связка | Явный шаблон, чеклист или механическое зеркало |
| question_quality | Если вопрос есть, он конкретен и открывает исследование; полезный ответ без вопроса тоже получает 2 | Вопрос полезен, но слегка общий или перегруженный | Вопрос фактически повторяет утверждение либо не даёт полезного фокуса |
| proportionality | Глубина и длина соответствуют материалу | Есть немного лишнего текста или недоразвитый фрагмент | Длинный общий ответ на минимальный материал либо явно недостаточный ответ на содержательный запрос |

Баллы не определяются длиной автоматически. Короткий ответ может быть сильным,
а длинный — пропорциональным богатому материалу. «Я не знаю» не требует заполнения
паузы: короткое разрешение остаться без ответа может быть сильным продвижением
именно в таком контексте. Простое повторение ключевых слов само по себе не
доказывает специфичность. Рубрика не требует непременно нового вопроса или темы.

## Q-флаги и доказательства

| Флаг | Смысл | Связанное измерение |
|---|---|---|
| Q01_GENERIC_REFLECTION | Общий отражающий отклик без специфического смысла | contextual_specificity |
| Q02_UNNECESSARY_PARAPHRASE | Избыточный пересказ слов пользователя | non_repetition |
| Q03_REPETITIVE_STRUCTURE | Неоправданно повторяемое строение нескольких ответов | non_repetition |
| Q04_LOW_PROGRESSION | Отсутствие полезного движения исследования | progression |
| Q05_GENERIC_QUESTION | Общий вопрос вместо осмысленного конкретного фокуса | question_quality |
| Q06_TEMPLATE_LANGUAGE | Очевидно шаблонный или механический язык | naturalness |
| Q07_CONTEXT_MISS | Существенный контекстуальный промах | contextual_specificity |
| Q08_OVERLONG_OR_UNDERDEVELOPED | Несоразмерная длина либо недоразвитость | proportionality |

Флаг требует конкретного доказательства. evidence — непустая точная цитата из
candidate_response, user_message или одного сообщения conversation_context.
Для повторов цитата якорит конкретный паттерн, а reason объясняет его сопоставление
с предоставленными ходами. Подсказка о паттерне или общий комментарий не заменяет
цитату. Валидатор проверяет наличие цитаты, но не доказывает её смысловую силу.
Не следует ставить флаг только из-за наличия балла 1. Флаги не обязательны для
каждого балла 0/1, если слабость конкретно объяснена в reason.

## Контракт результата

```json
{
  "scores": {
    "contextual_specificity": 2,
    "progression": 2,
    "non_repetition": 2,
    "naturalness": 2,
    "question_quality": 2,
    "proportionality": 2
  },
  "quality_flags": [],
  "overall_quality": "strong",
  "reason": "Ответ работает с конкретным различением и соразмерен текущему материалу.",
  "insufficient_context": {"present": false, "items": []}
}
```

Каждый элемент quality_flags имеет только flag_id и evidence.
Каждый элемент insufficient_context.items имеет только dimensions (непустой
массив уникальных имён измерений), missing (непустая строка) и reason (непустая
строка). Множество перечисленных missing dimensions точно совпадает с множеством
измерений со значением null. present=true тогда и только тогда, когда есть items
и есть хотя бы один null. Нельзя заменять неизвестность нулём или ставить null
для обычной слабости. Доказанная слабость одного измерения не исчезает из-за
неизвестности другого.

## Итог и приоритет

Это derived_product_quality_criteria, не методологическая система hard fail:

1. Есть хотя бы один доказанный 0 → weak, даже при пробеле в другом измерении.
2. Нет 0, но есть существенно неизвестное измерение → insufficient_context.
3. Нет 0/null, есть хотя бы один 1 → acceptable.
4. Все шесть баллов 2 → strong.

Для однозначного офлайн-контракта strong требует все 2. Вариант «большинство 2»
не выбран, чтобы не пересекаться с acceptable. Условие существенно недостающего
контекста — смысловая ответственность оценщика; валидатор проверяет декларацию.

## Правила реализации и корпуса

implementation_contract_rule: неизвестные/отсутствующие поля на всех уровнях
отклоняются; bool не считается числовым баллом; идентификатор Q-флага уникален;
его связанное измерение имеет 0 или 1. HF-идентификаторы запрещены. Данные
копируются; исходный объект не изменяется. Цитаты не нормализуются, включая е/ё.
Эти ограничения — поведение реализации, а не прямые правила Ольги.

corpus_format_rule: JSON-конверт версии 1.0 содержит schema_version, language=ru,
synthetic=true, provenance=derived_product_quality_criteria, specification,
description и cases. Каждый кейс содержит id, title, synthetic, provenance,
input и expected. ID уникальны. Метки — производные синтетические оценки качества,
не слова Ольги и не методологические HF-ожидания. Загружаются только файлы под tests/.

Офлайн-проверка доказывает форму и согласованность меток, но не качество неизвестной
модели. Будущая квалификация должна отдельно проверять оценки измерений, Q-флаги,
работу с контекстом и полное структурное совпадение. Подключение модели/runtime
не входит в эту фазу.
